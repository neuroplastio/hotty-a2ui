# 2026-10-10.22 — KIT-27: schema validation is optional

The docs viewer, a program that is its own agent, linked A2UI's JSON
Schema validation it has no use for: jsonschema, x/text (only for
jsonschema's messages) and the compiled schemas, 0.42 MB of its js/wasm
gzipped (journal 2026-10-10.21).

- `a2ui.Validator`: an interface for the three checks the core made
  against the schemas, a message's envelope, a component's definition, a
  function call. `Processor.Validator` is nil from `NewProcessor`: the
  processor still checks what applying a message needs (one action, its
  surface, types, references, reserved keys, nesting) and trusts the rest
  to its agent.
- `a2ui/schema` holds what `a2ui/schema.go` did: `Validator` (A2UI's,
  each catalog compiled once, shareable), `NewProcessor` (a processor
  with it), `CheckCommonType`. `Catalog.CheckComponent` and `CheckCall`
  are gone; `(&schema.Validator{}).Component(c, def)` is the same check.
- Who keeps it: the conformance suites, and the story package, so the
  storybook (its stories and `-stream`, A2UI another program wrote) checks
  as before. The view and rendition tests build trusted processors, and
  still pass.
- Without a validator nothing panics on bad input: the conformance suites
  run against a bare processor fail only the 10 cases that expect a schema
  error.

The probe that uses the kit as the docs do: 11.4 MB → 9.7 MB, 2.89 MB →
2.46 MB gzipped. The rest is the renditions, which link every component;
a registry to split them waits for the maintainer to say it matters.
