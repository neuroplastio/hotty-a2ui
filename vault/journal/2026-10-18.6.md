# 2026-10-18.6 — KIT-PICKER: Tab completes, on a host too

The maintainer: "tab is supposed to autocomplete, not switch focus". In
cells Tab went past the picker to the next focusable element; on a host
it is the host's (SPEC §10.2 ignores a binding of `tab`), and it left
the input.

**Now Tab completes the query to the selected row:** the row's new
`complete` (a command's name to type arguments after), else its title.
It is written as the agent's queries are (view.Pick.Written), so a host
has it in a new input, and the caret goes to its end (cells' pickCaret).

**On a host,** within the SPEC: the input sits between two stops of the
picker's, focusable and unseen (`~m` before it, `~n` after it, the
cycle's parts). Tab lands on the one after, and the host says so (a
`focus` event): the picker completes. Shift+Tab lands on the one before,
and does nothing. Either way the next Update gives the input the keyboard
back. A part id is one letter and digits (viewID), so `ha`, the first
try, was dropped as no part at all.

**Checked:** the gate; TestPickerTab; a vector on both renditions (`zo`,
Tab, `Zoom`, then `x` types `Zoomx`).
