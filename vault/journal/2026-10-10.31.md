# 2026-10-10.31 — KIT-20c: HottyQRCode

The phase-1 leg of KIT-20: a QR code for a phone's camera, as OpenTUI's
QR code draws it. Story `hotty/qr`: a URL's code bound to a text field
beside it, so that the code follows what is typed, and a Wi-Fi network's
code at error correction H, each with its label under it.

**The reference.** Bubble Tea has none, so it is OpenTUI's
`QRCodeRenderable` (`@opentui/qrcode` 0.5.17, MIT, added to
`ref/opentui` at the version of the core it has, so that `diff.ts` and
`toast.ts` run as before; `ref/opentui/qr.ts`, `make shot NAME=qr` with
`KIT_KEYS=` and `ROWS=48`). Its defaults are what the kit chose before
reading them: half blocks, a module a column wide and half a row tall, a
quiet zone of four modules, `#000000` on `#ffffff` whatever the theme,
level M. It has no label (the reference sets text under it), and where
the code does not fit it shows a `fallbackContent` or nothing. One thing
it does that the kit had not: it raises the level where the version
holds the value at a higher one (`boostEcl`, as Nayuki's library does),
so its URL code read back as Q where the kit's was M, at the same size.
The kit does so too now.

**The catalog** (profile §6.29, instruction 29). `HottyQRCode` takes
`value` (a DynamicString, required), `errorCorrection` (`L`, `M`, the
default, `Q`, `H`), `label` (a DynamicString) and `weight`.
- `value`, as A2UI's own components name what they hold, not `data`,
  which reads as the data model.
- `errorCorrection` by its letters, as every QR library and reader names
  the levels; the least the code gets (above).
- No size, colour or quiet zone prop: the size is the value's, and black
  on white with its quiet zone is what a camera needs. The instruction
  tells the agent to keep the value short and to give it in words too,
  for a user who cannot scan.

**The encoder** (`qr/`, a package of the kit's): rsc.io/qr v0.2.0's
`coding` (BSD-3-Clause, Russ Cox's; its only import is its own gf256),
added with `go get`, which builds a code of a given version, level and
mask; the kit picks them: the smallest version, digits, else QR's
capitals and marks, else the UTF-8 bytes; the level raised; and of the
eight masks the one ISO/IEC 18004's penalty rules (runs, 2×2 blocks,
finder-like patterns, balance) score lowest, where rsc.io/qr's own
`Encode` leaves mask 0 (its TODO). A cache of the last 32 codes, since
a view encodes at every rebuild and a field typed into rebuilds it.
skip2/go-qrcode (MIT) picks its mask itself, but in a probe encoding one
code it added 0.48 MB to a hello-world Go js/wasm (2.64 MB), against
0.14 MB for rsc.io/qr's `Encode`, and the kit takes `coding` alone; size
is what KIT-27 cut for.

**Cells** (`rendition/cells/qrcode.go`): its modules two to a cell in
`▀ ▄ █`, a quiet zone of four (4 columns each side, 2 rows above, 2½
below), and its label centred under it. A dark terminal is the question
the leg had to answer: `fg` on the terminal's background would draw a
dark terminal's code light on dark, reversed, which ISO/IEC 18004:2015
lets a reader take but does not make it (ZXing only with its
`ALSO_INVERTED` hint). So a cell can be paper (`Cell.Paper`): black
on white whatever the theme, the one place cells names colours besides
a HottyProgress's magenta (§3.6). At the floor that is
`38;5;232;48;5;231`, the 256 colours' darkest grey and white, which a
palette that sets the sixteen (and base16-shell, which sets 16 to 21)
leaves alone; in a theme that paints its own background,
`38;2;0;0;0;48;2;255;255;255`. Under NO_COLOR it is the glyphs alone:
dark on a light terminal, reversed on a dark one. Natural width and
minimum: the code's, which does not shrink; a box narrower anyway (a
narrow terminal, a Row) shows the label and the value as text, since a
code cut does not scan. Too long a value: `✗ Too long for a QR code`.
`https://hotty.neuroplast.io/a2ui`, labelled `Scan me` (the quiet zone's
rows are blank here, paper in the terminal):

**HTML:** an inline `svg role=img` named `QR code:` and the value: a
`viewBox` a module a unit, a white `rect` and one black `path`, a
rectangle a run of dark modules across a row, `crispEdges`, so that a
new value is one attribute's delta (`~c`); `--k-modules` half rows a
side, a module as large as in cells, `max-width: 100%`. Its label under
it. The host's own look is KIT-20h.

**Text:** `Label: value`, the value alone without a label, whether a
code holds it or not.

**Checked that it scans:**
- A scratch program (`.shots/qrprobe/scan`, gozxing, ZXing's Go port,
  Apache-2.0, not in the module) puts values through a HottyQRCode,
  draws the surface in cells with text round it, rasterises the frame's
  paper cells (`▀ ▄ █` the dark halves) and decodes it with ZXing's
  detector, not its pure-barcode path: 34 codes, digits, capitals, URLs,
  a Wi-Fi string, UTF-8 with accents and kanji, versions 1 to 36, every
  level, all read back as their values, at the level asked or above
  (two values too long for Q and H are the error). zbar reads the UTF-8
  one too.
- The story's Plain frame, rasterised the same way: both codes.
- zbar and gozxing on the pictures: the reference shot (OpenTUI's two
  and the kit's two, Catppuccin Mocha); the story in Catppuccin Latte
  after typing `/docs` into the field (the code read
  `https://hotty.neuroplast.io/docs`); the story in the kit's Dracula
  theme, truecolor paper; `hotty render` at 1.6x of the story's HTML,
  terminal and material light. Every code read.
- Tests: `qr` (versions and capacities, the levels raised, finder and
  timing patterns, the chosen mask scoring lowest of the eight, the
  penalty), view (mapping, a bound value re-encoded, too long, empty),
  cells (Plain read back into modules equals the code and its quiet
  zone, every cell paper; the floor's and a theme's SGR, NO_COLOR's
  glyphs; the narrow fallback, the error, empty; a Row), html (the svg,
  the path read back into the code's modules, before and after a delta),
  text, and catalog validation.

Pictures, each looked at: `.shots/qr.png` (OpenTUI beside the kit:
the same size and look, different masks), `qr-latte.png`,
`qr-dracula.png`, `qr-host.png`, `qr-host-light.png`.

**Open for the maintainer:**
- NO_COLOR draws a dark terminal's code reversed. Black and white are
  not the colour NO_COLOR is about, and keeping paper there would read
  everywhere; the kit keeps NO_COLOR's rule (no colour at all) until
  told otherwise.
- The floor's paper is 256-colour SGR, a step past the ANSI-16 floor; a
  16-colour terminal would show its own nearest, which may be a theme's.
- The level is raised where it is free; an agent that wants exactly M
  gets at least M.
- A box narrower than the code shows text, not a smaller code: quadrant
  blocks would halve its width but make its modules twice as tall as
  wide.
