# 2026-10-10.28 — KIT-25 and KIT-26: HottyMarkdown, links in place

Both legs (c and h) of KIT-25 and KIT-26 for the docs sites (gov
NEIO-14): long-form Markdown read as GitHub reads it, and links that the
renderer or the agent follows in place. Story `hotty/markdown`: a docs
page for a made-up tool, Lovelace, in a HottyScrollView 16 rows tall. It
has an h1 and its intro with three links in place, a TIP, a
`<!-- docs:figure -->` marker before a portrait (an https image), an
Install section with a `sh` block and a table, and a Configuration
section with a WARNING and an ordered list. Then a FAQ with a link that
has a scheme (Wikipedia), a relative one, and "the top". Under the box,
a caption shows `/page/link`, then a HottyKeyHints.

**The component.** `HottyMarkdown` (catalog-naming: Hotty and the plain
noun; A2UI's own word for it is Text, which promises "simple Markdown").
Its props are `text` (a DynamicString, required), `link` (a
DynamicString), `onLink` (an Action) and `weight`. It is a component of
its own, not an option on Text, for three reasons. First, its layout is
a page's: blocks a blank row apart, callouts, tables drawn as a
HottyTable's. Second, its links are Tab stops, which a Text's must not
become. Third, a docs page is a different thing to ask an agent for.
The catalog has instruction 27, and the profile has §6.27. HottyTree's
nodes take an optional `href` (catalog `treeNode`, `TreeNode.Href`).
The view keeps it and no rendition draws it; a page mode that follows
it is KIT-24's.

**Reading** (`view/document.go`, `view.ReadDoc`, cached by source):
goldmark with GFM and an AST transformer for alerts. A top-level quote
whose first line is `[!NOTE]` … `[!CAUTION]` (case aside) becomes an
alert node, its marker taken out. A quote inside a list or another
quote stays a quote, as on GitHub. HTML blocks and inline HTML are
dropped, comments too, so a `docs:` marker shows nothing and the block
after it shows normally. An image is `[image: alt]` in cells and text,
an `img` on a host. Blocks carry their frames (item, quote, alert),
outermost first, and the renditions draw the frames as prefixes. The
host's HTML is goldmark's, with renderers for links, alerts and HTML at
a higher priority (`view.DocHTML`). Tables, strikethrough and task
boxes use goldmark's exported GFM renderers.

**Heading IDs** follow github-slugger, not goldmark's auto IDs (which
come from the source line, so `## See [docs](url)` differs):
- the heading's text content (code and link text in, an image's alt
  out), lower-cased;
- every character that is not a letter, a mark, a number, a connector
  or `-` is dropped, and each space becomes `-`;
- a repeat gets `-1`, `-2` from an occurrences map, so `Usage`, `Usage`
  and `Usage-1` give `usage`, `usage-1` and `usage-1-1`.

The IDs run across the surface in tree order (`anchor` in Build): a docs
page split into several HottyMarkdowns numbers as one page. On a host, a
heading's id is `<doc>~#<id>`, encoded as every DOM id is. `~#` can't
come from anything else, because a node key's `#` encodes as `~23` and
part ids are `~` and a letter. So `viewID` reads it back as its
document.

**Links.** `view.InPlace`: an href with no RFC 3986 scheme (and not
`//host`) goes in place. Each link in place is a child element, Kind
`Link`, id `<doc>/link/<i>`: a Tab stop that Enter or a click follows
(`Controller.FollowLink`).
- A `#fragment` that names a heading on the surface (percent-decoded,
  then retried in lower case) is the renderer's. The heading's document
  takes the keyboard, and `State.Jump` records the jump, with a sequence
  number so a rendition scrolls once per jump. Nothing is sent.
- Any other href, or a fragment that no heading has, is the agent's. It
  is written to `link` (bound, else the renderer's state), then `onLink`
  runs, its context reading the path. This is the §6.26 pattern: an
  action carries no payload.
- Tab after a jump goes on from the heading (`afterJump`), as a browser
  does from a fragment: to the document's next link, or past the
  document.
- A link with a scheme stays a Text's: OSC 8 in cells, `target=_blank` on
  a host.
- Hints: `enter open`.

**Cells** (`rendition/cells/document.go`):
- **Blocks:** a Text's look with a page's rhythm. A blank row comes
  between blocks, but not between a tight list's items, and not after an
  alert's title. Inside a quote or an alert, the blank row keeps the bar.
- **Frames:** a marker and its margin, or `▎ ` (in `border` for a quote,
  in the alert's tone for an alert). Frames drop where they leave no
  room.
- **Alerts:** a title row of the mark and the title, bold in the tone
  (`ⓘ Note`, `✓ Tip`, `★ Important`, `! Warning`, `✗ Caution`; info,
  success, accent, warning, error).
- **Tables:** a HottyTable's header and rule. Columns are fitted by the
  table's own rule, factored out as `fitWidths`, and a cell wraps rather
  than being cut.
- **Code:** two columns in, highlighted.
- **Links in place:** underlined with no OSC 8, a hit per run (a glyph
  now carries `hit`), the box being the first row. A focused link is
  reversed in the accent.
- **Jump:** the target heading's rows are the document's reveal, and
  `revealFocus` puts that box at the top of an enclosing HottyScrollView
  once per jump (`Rendition.jumped`). After that, the wheel and keys
  scroll freely.

**Host** (`rendition/html/document.go`):
- **Root:** `div.k-text.k-doc`.
- **Headings:** an `id`, and `tabindex=-1` so that `a=focus` reaches
  them (`focusOn` gives the heading's id while the document has the
  keyboard after a jump). They get no outline.
- **Links in place:** `span.k-link role=link tabindex=0 data-on=click
  data-keys="Enter=program"`. It is a span because hottytest's host does
  not focus an `a` without href, and SPEC gives an `a` Space and Enter.
  Its click reports the id (SPEC §9), Enter goes to the program, and the
  html rendition's Key follows it. It is filled with `--k-focus` on
  `:focus`, as a Button is.
- **Alerts:** `div.k-alert.k-alert-<kind> role=note`, a 3px bar in the
  tone, then a `p.k-alert-title` with the icon (`info`, `lightbulb`,
  `feedback`, `warning`, `report`; three new names in icons.txt,
  regenerated) and the title. IMPORTANT is `--k-focus`.
- **Spacing:** `--k-3` between blocks, more before headings.

**Text:** the blocks a blank line apart, framed as in cells; a table
two spaces between columns; code as it is; a rule `───`.

**Open for the maintainer:**
- IMPORTANT is the accent: GitHub's purple has no role.
- IDs number across the surface, as one page. A heading in a hidden tab
  isn't built, so it isn't numbered.
- Space on a link in place does nothing in cells. SPEC §10.2 gives a
  span that only reports clicks no keys, but hottytest's host clicks it
  on Space (and Enter, which the keymap gives to the program here).
- Keys a focused link doesn't take don't reach an enclosing
  HottyScrollView in cells; on a host the box's `data-keys` are
  inherited.
- After a jump, nothing marks the document as focused. The heading at
  the top is the sign, and the host's heading has no outline.
- On a host, a `#fragment` scrolls only where the document scrolls
  (SPEC §5.3), and only into view, not to the top. In a surface that
  doesn't scroll, the program hears nothing that would place the
  heading. No SPEC change was asked for.
- An unbound `link` leaves `onLink` with nothing to read.
- A quote holding only `[!NOTE]` is still an empty alert. Alerts are
  read at the top level only, as on GitHub.
- An inline comment between two words leaves their two spaces.
