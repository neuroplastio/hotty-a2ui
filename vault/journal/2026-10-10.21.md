# 2026-10-10.21 — From the docs: an unfocused tree's selection, the kit's size

The docs pilot's nav is the kit's HottyTree now (web branch `docs-pilot`,
the docs agent, 2026-10-10). Two things it asked the kit to decide.

**An unfocused tree's selected node** (KIT-09c's look). In cells it was
the bar alone, `│` in `muted` in column 0, which beside the guides read as
a stray guide; in a docs nav the selection is the page you're on, and
matters most while the tree doesn't have the keyboard. Its label is bold
now, in the text's colour; with the keyboard it is the accent and bold,
as before. On a host the selection keeps its tonal background either way.
For the maintainer's look in the next round. HottyList's unfocused
selection is the same bar with plain text, as bubbles' list draws it;
left as it is until the maintainer says.

**Size.** The docs viewer's Go js/wasm went from 8.9 MB (2.4 MB gzipped)
to 16 MB (3.9 MB) for one HottyTree. A probe that uses the kit as the
docs do (`NewProcessor(basic, hotty)`, a controller, cells and html):
11.4 MB, 2.89 MB gzipped, against 2.6 MB (0.76 MB) for a program that
prints a line. Without the schema validation (jsonschema, x/text, the
compiled A2UI schemas; a stub `schema.go` for the measurement) it is
9.7 MB, 2.46 MB gzipped: 1.7 MB and 0.42 MB of the kit's 8.8 MB and
2.1 MB. The rest is the renditions and what they draw: goldmark (Text),
chroma and regexp2 (Code), hotty-go's charts, the view. They paint every
component from one switch, so a program links them all; splitting them
by component means a registry, a larger change. On the board as KIT-27.
