# 2026-10-11.6 — HOTTY 0.2: hotty-go bf2b88d, msgpack bodies

gov's P-3 release order: the kit moved from hotty-go 1ddaac3 to bf2b88d
(root, hottyedit, hottytea, hottytest; hottyterm comes in through
hottytea), HOTTY 0.2 with msgpack bodies and the version handshake. It
was built first, ahead of web and the docs pilot, which could not build
against bf2b88d while the kit called 0.1's methods. It was kept on a
local branch (`p3`, worktree `hotty-a2ui/p3`), rebased as main moved
(11607f8, 9fa50d5, 4b74875), and tested by web and docs through their
go.work. It went to main as 4b74875 on gov's word, after plx
(859dc780), hottyterm (26.10.10-dev.3f47526) and the addon's
0.1.0-next.8 on npm.

What changed in the kit:

- An event's detail is fields: `Checked`, `Value`, `Drag`, `Area` and
  `Hover` in rendition/html, `FitRows` in the storybook. The storybook
  had read the fit as JSON from the detail, which fails without an
  error under msgpack; two storybook tests (the pickers' height, the
  story under the panel's bar) caught it.
- `Caps.Hovers` and `Reply.Err` are `hotty.Hovers` and `hotty.Err`;
  tests read a command's keys with `hotty.Get`.
- hottytest goes on from the focused element after a jump (a4025c0), so
  the vector "Tab from a heading a #fragment went to" plays on the host
  too, no longer cells only.

Nothing in the new API was awkward enough to report to hotty; the only
friction is `ev.Checked != nil && *ev.Checked`, at two sites.
