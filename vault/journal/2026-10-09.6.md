# 2026-10-09.6 — Another story's surface after F2

Reported by the maintainer: in the storybook pane, F2 to cells showed
basic/32_advanced-form-validator's surface, with text typed into it,
over hotty/progress in cells.

The surface wasn't this process's. It was left by an earlier storybook
in the same pane.
- `plx pane exec --replace` ends the pane's program with SIGKILL. A
  script trapping TERM, HUP, INT and QUIT logged none of them. The next
  program runs on the same pty, still in the alternate screen.
- So the old program deleted nothing, and the alternate screen was never
  left, which would have removed its placements (SPEC.md §5.4). Its
  surfaces stayed placed, and only a surface of the same name covers
  one. In surfaces mode the new story's surface hid it; in cells nothing
  did.
- Inside one process the storybook leaves nothing behind when a story
  changes or F2 moves to cells (storybook TestNoSurfaceLeftBehind).

Fixed on the kit's side: the storybook now ends on TERM, HUP and INT as
it does on Control+C, deleting its surfaces first (cmd/storybook
`endOnSignal`). Bubble Tea's own handling quit without that. This does
nothing for SIGKILL.

Filed with the hotty agent: plx replaces a pane's program with SIGKILL
and leaves the old program's surfaces on the host (plx passes HOTTY
through to hottyterm). The SPEC's rationale for detach says that what ran
a program can clean up after it. The pane launcher in this session now
resets the terminal (RIS) before starting the storybook.

Also seen while probing: with the pane not visible, the host answered
`a=q` but none of the `a=hide` commands sent with `q=0`.
