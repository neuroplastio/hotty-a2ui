# 2026-10-18.1 — KIT-PICKER: HottyPicker, a command palette's picker

plexos is redoing its command palette after Zed's, VS Code's and
Raycast's, drawn with the kit (plexos p/palette-revamp). The maintainer:
"I don't think palette fits into any existing components except text
input with auto complete", and took the lean of a picker of the kit's
own (plexos d/palette-picker). A TextField's suggestions are strings the
renderer start-matches, five at most, with one act (take the value) and
no list on a host (KIT-11h); a HottyList filters by itself after `/`,
with one action.

**How an agent asks for it.** `HottyPicker`, instruction 33:
- `query`, bound, which the picker writes as the user types, then runs
  `onQuery`; the agent answers by writing `rows`, best first. The picker
  never filters or ranks.
- A row: `value`, `title`, and optionally `group` (`Group: Title`),
  `detail`, `section` (a heading where it changes) and `match` (the
  title's matched characters, `[from, to)` character ranges).
- A row's `actions`: `{id, title, key}`, the first Enter's, the others on
  `mod+enter`, `alt+enter`, `shift+enter` or `shift+delete` (the
  schema's enum): keys that type nothing and that no field edits by. An
  action writes the row's value to `selected` and its id to `action`, then
  runs `onAction`.
- `panelKey` lists the selected row's actions in the rows' place;
  `status` and a bindable `statusKind` (`error` or info); `loading`,
  `emptyText`, `placeholder`, `chip`, `height` (lines, 10 by default).

**What it does** (`view.Controller.PickerKey`, shared):
- ↑ ↓, ctrl+p, ctrl+n move the selection round; page keys by the lines
  shown. A change to the query writes `""` to `selected`, so the first
  row of the agent's answer is selected. The lines follow the selection,
  a row's heading with it; a heading on the last line, none of its rows
  under it, is left out.
- The query is a one-line field's: cells edits it with editKey, and the
  host rendition with hottyedit too (`pickEdit`), the box's keys being
  the program's. So what the agent writes to `query` shows at once, which
  a host's own input wouldn't while focused (SPEC §6.2). A host draws the
  program's caret (`k-caret`).
- Cells: the chip in the accent, the query, a rule, the status (`✗ ` in
  `error`), the lines (headings muted and bold; `Group: ` muted, the
  title, its matches in the accent and bold, the detail muted, the other
  actions' keys right-aligned and muted), the selected row reversed in
  the accent across the picker, as the suggestions' list draws its
  highlight; then a key-hints line: `↑/↓ move • enter <action> • ctrl+k
  actions`. The panel keeps the picker's height.
- Host: `div.k-pick` (`role=combobox`), rows `role=option` with
  `aria-selected`, matches in `k-match`. Page mode shows every row.
- Text: `? ` and the query, then the rows under their headings, `> `
  marking the selected one, a row's keyed actions after a dash.
- Clicks: a row selects; a second runs its first action; on the query,
  the caret goes there (cells).

**Story:** `hotty/picker`, "Picker": a terminal multiplexer's palette
(commands, panes, an agent), with the palette's agent behind it in the
storybook (`story.pickerProgram`): it ranks with sahilm/fuzzy over
`Group: Title`, as HottyList's filter does, and says in the status what
each action did; htop's pane is on bastion, which doesn't answer, so
its actions answer an error. `story.PickerRows("")` is the story's first
`/rows`.

**Reference:** `ref picker`, bubbles' list (bubbles has no palette); the
shot `.shots/picker.png`, both sides at 80×24.

**Look points** (not asked yet): the selected row reversed in the accent,
as a menu's, where a HottyList draws a bar; the keys as muted text, where
VS Code draws keycaps; `ctrl+enter alt+enter` take a lot of the row on a
narrow picker; the rule under the query.

**Checked:** the gate; the story in cells in VHS (empty, typed, the
panel); the page in Chromium (`storybook -page`), not in hotty-blitz,
which wasn't built here; keys and clicks in tests in view, cells, html
(hottytest) and vectors on both.
