# 2026-10-10.9 — KIT-11c: suggestions in cells

A phase-1 leg: values a one-line TextField offers as the user types, the
rest of one faint after the caret for Tab or → to take, and a list of
them under the field, as the select's open list is. Story `hotty/suggest`,
under Components: Command (git's commands, `git c` typed, the keyboard
on it), Country (empty, with an `onInput` whose context is the typed
value, which an agent answers by rewriting the list; the storybook only
logs it) and City (`Atlantis`, which none of its options extends), in a
HottyForm with the key hints.

**The reference.** bubbles' text input (`ShowSuggestions`,
`SetSuggestions`, v2.2.1): a prefix match after `strings.ToLower`, none
while the value is empty; Tab takes the current one, keeping the typed
case and appending the rest; ↓ and Control+n, ↑ and Control+p move
through the matches, round from either end; the ghost is colour 240, and
there is no list. huh's Input has the same with `SuggestionsFunc`, and
takes with Control+e, since Tab moves on in a form. `ref suggest` is the
story's three fields as bubbles' inputs, Tab moving on when there is
nothing to take, as the kit's does. `make shot NAME=suggest KIT_KEYS=
COLS=60 ROWS=22`, and with `Down Down` on both sides.

**The shape** (profile §6.22, instruction 22):
`metadata.extensions.io_neuroplast_hotty.suggestions` on a basic
TextField, `{"options": DynamicStringList (required), "onInput": Action}`.
An extension, not a `HottyAutocomplete`, because:
- the field stays a basic TextField: its `label`, `value`, `placeholder`,
  `checks`, `variant`, its keymap (`keys`, §10.2), `autofocus`, its Enter
  in a HottyForm and its place in A2UI's examples all keep working, with
  nothing re-declared. A component of its own would re-declare all of
  them, which is a fork of a basic component (AGENTS.md);
- a renderer that doesn't know it ignores it and shows a plain field that
  edits, which is the right fallback for suggestions;
- the catalog already adds behaviour to basic components this way: `fill`
  on a Slider, `icons` on Tabs and ChoicePicker, `reorder` with `onMove`
  on a List, `drop` with an `action` on anything.

`onInput` is there because basic's TextField has no action and A2UI has
no notice of a data change: without it the agent can't hear the typing
it is to answer. It runs after every change the user makes to the value,
a taken suggestion too. An action carries nothing (L2), so its context
reads the field's bound path; with `sendDataModel` each one carries the
whole model (L5), which instruction 22 warns of. `metadata` is static in
the core, so the renderer resolves `options` in the field's scope itself,
as `drag.value` already does.

**The rules** (`view/suggest.go`):
- **Match** in the renderer, at each key: the options that start with the
  value, case aside (simple folding, rune by rune), in their order; not
  the value itself, and none while it is empty. So the list is right
  while the agent's rewrite is on its way, and a closed set works with no
  agent at all. An empty option and a repeat are left out.
- **Nothing is highlighted** while the user types, unlike bubbles, whose
  first match is always current: Enter then submits what was typed, as a
  field's Enter does. The ghost shows the first match. ↓ or Control+n
  highlights the first, ↑ or Control+p the last; the ghost follows the
  highlight.
- **Tab** takes the ghost's suggestion; with none, or once taken, it moves
  focus as ever. **→** takes it at the value's end with nothing selected,
  else moves the caret. **Enter** picks the highlighted one, else
  submits. **Escape** shuts the list until the next edit, else goes on
  as ever (a Modal's close).
- **A taken suggestion is the value as written** in `options` (`sw` takes
  `Sweden`), as fish does, not bubbles' typed case plus the rest
  (`sweden`): the agent's list is the spelling it wants back. The list
  shuts until the next edit.
- **The highlight is kept by its text**, not its index, so it stays put
  while the agent rewrites the list around it, and is dropped when the
  value changes.
- At most **5 rows**, moved as little as keeps the highlight in view, then
  a count row.
- One-line fields only: not a `longText`, whose arrows move between
  lines, nor an `obscured` one, whose suggestions would show what it
  hides. A DateTimeInput ignores it.

The state is the controller's, `view.State.Suggest` (`At`, `Hi`,
`Closed`), shared by the renditions, and the list's first row reuses
`Scroll`. The element has `Suggestions` (all of them, non-nil whenever
the extension is there), `Shown`, `Selected`, `Top` and `Height`, as a
select's list has.

**Cells** (`rendition/cells/suggest.go`, profile §3.5, §3.7): at 30
columns, `git c` typed:

```
┃ Command
┃ > git commit
┃   git commit
┃   git checkout
┃   git cherry-pick
┃   git clone
┃   git config
```

- The ghost, `ommit`, is `muted` and faint, cut at the field's edge; the
  terminal's caret stays at the value's end, on the ghost's first cell.
- A row is the typed part plain and the rest `muted`, aligned under the
  value. The highlighted row, ` git checkout ` from column 3, is reversed
  in `accent`, a column of padding either side. First it was `> ` in the
  accent and bold, as the select's list has it; under the field's own
  `> ` prompt it read as a second prompt, so it is a menu's reversed item
  instead.
- Past 5: `┃   1–5 of 7` in `muted`.
- Empty: `┃ > git …`, the placeholder; no match (`hg`): `┃ > hg`; the
  list shut or taken: the value alone. Without the keyboard: a plain
  field.
- A click on a row takes it, the caret after it.
- Key hints: `tab complete • ↑/↓ suggestions • enter submit` while a
  list shows (`enter pick` once one is highlighted), and a group of its
  own in the full help.

**The host** (profile §2): the `input` names (`list`) a `datalist`
(`~x`, the part id the select's list uses) of the options, which deltas
keep up with the agent's rewrites; a host that draws a datalist shows its
own list, and its pick comes back as `input`, which runs `onInput`.
Blitz draws none (`hotty render` showed the field alone), so on
hottyterm the field is plain and edits, with no `! Type`. Whether the
xterm addon's DOM shows it is unchecked. The kit's own list, ghost and
keys are KIT-11h, because:
- a host keeps Tab: SPEC §10.2 has hosts ignore a binding of Tab,
  Shift+Tab and Escape, so Tab can't take a suggestion there;
- a host leaves the value of the field it has focused alone (SPEC §6.2),
  so a taken suggestion can't be written into the field without a blur
  and focus handover, the one the select uses and KIT-SEL wants gone.
ArrowUp and ArrowDown reach the program in an `input` (they're
multi-line actions) and Control+n and Control+p are line-next and
line-previous in TerminalKeys, so the moves could be bound; picking
can't, so none of it is half-built.

**Text:** the field alone (`Command: git c`): the suggestions show while
it has the keyboard, which a pipe never gives it.

**Vectors** (`vectors/keys.yaml`): one in both renditions, the field
editing as ever with suggestions on it: typing runs `onInput` at each
change with the value in its context, Tab with nothing to take moves on,
Enter submits. Two on cells alone: Tab and → taking, and Tab then moving
on; ↓, ↑, Control+n and Control+p round from either end, Enter picking,
Escape shutting and Enter then submitting, ↓ reopening. A vector now
takes `renditions:` to name where it plays; these say why in their
names. The host's half can't play: hottytest draws no datalist, and a
host keeps Tab.

**Checked:** `make check`; the unit tests (matching, taking, moving, the
window; the cells rows with roles and attributes, empty and no-match, a

`input`); the storybook in vhs (Command, then Country with `S` typed and

**Open, for the maintainer**, each a proposal:
- Nothing highlighted until an arrow, so that Enter submits what was
  typed. Proposed to keep; the other way is bubbles', the first match
  always current, and then Enter would pick it.
- The highlighted row reversed in the accent rather than the select's
  `> `, which read as a second prompt. Proposed to keep, and to leave the
  select's list as it is.
- A taken suggestion as written in `options`, not bubbles' typed case
  plus the rest. Proposed to keep, since the agent's list is the
  spelling it wants back.
- Five rows. Proposed to keep: the list pushes the form down, as the
  select's open list does, until KIT-11h floats it.
- `onInput` at every change, with no debounce. Proposed to keep: the
  renderer narrows meanwhile, so a slow agent shows a right list; a
  debounce would be the agent's, or a `debounce` field later.
- Prefix matching only, case aside. Proposed to keep, since the agent can
  match otherwise and rewrite the list, but the renderer still narrows
  to prefixes, so a fuzzy agent's extra matches don't show. If that
  matters, a `match` field (`"prefix"`, `"none"`) would let the agent's
  list show as sent.
- On a host, the datalist as the baseline. Proposed to keep: it's free
  where a host has it, harmless where Blitz hasn't, and KIT-11h replaces
  it. Tab and picking on a host need either the blur and focus handover
  or a SPEC change through hotty (a program-bound Tab in a field with
  suggestions); that's the maintainer's call, with KIT-SEL's.
