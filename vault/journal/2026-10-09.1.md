# 2026-10-09.1 — The vault, the gap analysis, and the plan

The maintainer asked for three things:
- the gap analysis against Bubble Tea and OpenTUI, saved with a ticket for
  each gap;
- a way to name new components so they don't collide with components A2UI
  adds later;
- a check that A2UI can carry what those components need.

They also set the order: cells parity first, then the HOTTY layer.

- **The vault.** It follows the layout of the other neuroplastio vaults.
- **The gaps.** [knowledge/gap-analysis.md](../knowledge/gap-analysis.md)
  lists 21 gaps, KIT-01 to KIT-21. Each one says what cells parity means and
  what HOTTY adds.
- **A2UI's limits.** [knowledge/a2ui-limits.md](../knowledge/a2ui-limits.md)
  finds no gap that needs A2UI to change. Four limits shape the designs:
  - L2: actions carry no renderer payload, so components select, then act.
  - L4: the data model has no append, so streams arrive as chunks.
  - L5: `sendDataModel` sends the whole model with every action, so big
    content goes in props.
  - L10: nothing in A2UI governs local resources, so the program grants
    roots and registers commands.
- **Naming.** [Q-0001](../knowledge/catalog-naming.md) is open. The
  lean is a `Hotty` prefix (`hotty` for functions), following upstream's
  advice to put components in custom catalogs and the precedent of its
  composite sample (`MaterialTable`).
- **The board.** [tasks/board.md](../tasks/board.md) has phase 1 (`c` legs),
  then phase 2 (`h` legs), with KIT-REF and KIT-LOOK first.

Sources:
