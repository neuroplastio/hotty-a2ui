# 2026-10-09.9 — KIT-04c: HottyList

The fourth phase-1 leg, held against bubbles' list with its default
delegate (`make shot NAME=list`, bubbles' My Fave Things). Side by side
at 80×24 the two match in layout, glyphs and keys. The title badge is
the theme's accent, not bubbles' purple.

**The catalog** (profile §6.9, instruction 9):
- `HottyList` has `title`, `items` (`label`, `description`, `value`),
  `selected`, `onActivate`, `filterable`, `height`, `emptyText` and
  `weight`.
- `items` is one prop, literal or bound (L3, L5). An item's identity is
  its `value`, else its index, as a HottyTable's rowKey.
- Select, then act (L2), as the Table does.

**The view** keeps everything the renditions share:
- `Element.Shown` is the items the query leaves, best first. `Matched` is
  each one's matched byte offsets. `Top` is the page's first.
- The query is `State.Query`, the renderer's state, not the data
  model's. The agent sees the selection, not what was typed.
- The ranking is sahilm/fuzzy (MIT), the package bubbles' list uses. So
  "n" gives Nutella, Nice socks, Noguchi Lamps, Linux, Bitter melon in
  both, and "nu" puts Nuts before Nutella (fewer unmatched characters).
- `Controller.ListKey` serves both renditions, with bubbles' keys:
  - the arrows, j and k move;
  - ←/→, h/l and Page Up/Down turn a page, to the same place on it, and
    not past either end;
  - Home/g and End/G go to the ends;
  - `/` starts a filter, and each change selects the first match;
  - Enter applies the filter, and drops it when nothing matched, as
    bubbles does; Escape drops it.

**Cells:** bubbles' default delegate. Two columns in; the selected item's
two columns are `│ `. The status line reads `12 items`,
`“n” 7 items • 5 filtered`, `Nothing matched`. A body with a height keeps
its rows on every page and while a filter leaves fewer, so the list
doesn't jump. Lists without descriptions take one row an item, with no
blank rows between.

**HTML:** a focusable `role=listbox` box, as the Table is.
- The filter is typed through the program's keys there too. A focused box
  uses no keys (SPEC §10.2), so `/`, characters, Backspace, Enter and
  Escape all reach `ListKey`. `data-keys` binds the arrows, Page Up and
  Down, Home, End and Space, which a scrolling host would take. There's
  no host input, so no echo fights the typing.
- Hidden rows keep a paged list's height while it filters, as in cells.
- The focused selection and the filter prompt use `--k-focus`. In the
  Terminal theme `--k-accent` is the host's foreground, the fill of a
  primary button. The first live run in hottyterm showed the selection
  in the foreground colour, which is how this was caught.

**Checked:** view, cells and html tests; a key vector on both
renditions; `make shot NAME=list`; `hotty render` focused and filtering.
Live in headless hottyterm: a click, ↓ and `/nu` moved and filtered on
the real host. A second run's injected input didn't land (flaky
injection, nothing in the program), so the colour fix was checked with
`hotty render`.

For the maintainer to judge:
- the title as a badge in the accent (bubbles' is purple), and the
  unfocused selection's muted bar with plain text;
- the HTML look: a tinted selected item with a bar at its start;
- whether `filterable` should default to true, as bubbles' does. It's
  false, as ChoicePicker's `filterable` is;
- the Table has no j/k/g/G keys, which bubbles' table has.
