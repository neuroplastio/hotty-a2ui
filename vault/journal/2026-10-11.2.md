## elapsed

`HottyStopwatch.elapsed` is a DynamicNumber bound to a path. It holds the
time counted in whole milliseconds, as the last draw counted it, so a
lap's context reads what the user saw. It is written:

- before any action of the surface runs. Every action the view runs now
  goes through `Controller.invoke` (Tree.Invoke) or `Controller.dispatch`
  (Surface.Dispatch), which call `syncElapsed` first;
- when the stopwatch stops counting, at the draw that sees it stopped
  (TickTimers, which then rebuilds);
- when it is reset, as 0.

It is not written at a draw while it counts: the timer journal
(2026-10-10.24) ruled out rewriting the model ten times a second. Writing
only at a stop, as that journal proposed, would miss a lap taken while it
runs, so the write before each action carries that case.

It is written, not read: an agent writing the path doesn't set the time.
Two-way, a resumed stopwatch, would read back its own writes; not needed
yet. A HottyTimer has no `elapsed`. The maintainer's ok was for the
stopwatch, and a timer's time left would be a different number.

Test TestStopwatchElapsed covers a lap at 1.25 s (context ms 1250), a stop
at the 2.5 s draw (2500), a reset (0), no write while counting, and an
unbound stopwatch writing nothing. The story `hotty/timer` binds the lap to
`/lapMs`, with a caption under it. In VHS, stopped with s, it reads `Lap
3.8s` over `/lapMs: 3842 ms`; still running, it reads 0 ms.
