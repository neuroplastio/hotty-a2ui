# 2026-10-10.29 — KIT-24: page mode

For the docs (gov NEIO-14, *On the kit*): one of the docs' three modes is
a plain web page, read without JavaScript and by crawlers. Page mode
renders a surface into such a page, not a terminal: the host's markup,
with what only a program makes work left out and what a program would
show a piece at a time shown whole. A rendition mode, not a component:
no catalog instruction, the profile's new §2.1.

**The API** (`rendition/html/page.go`):
- `html.PageCSS() string`: the kit's stylesheet for a page, kit.css and
  then page mode's rules (`page.css`). A page puts it in once, in its
  head (a `<style>`, or a file it serves and links), however many
  surfaces it shows.
- `(*html.Rendition).Page() string`: a surface's markup alone, a fragment
  for the page's body. The rendition is the one a host gets
  (`html.New(controller, name)`, `SetTheme` as on a host); its name is the
  fragment's top element's id and prefixes every id in it
  (`<name>~~<id>`), and every attribute that names one, so a page's
  surfaces share none.
- `view.BuildPage(surface, state)`: the view `Page` draws. As `Build`, but
  a Tabs holds every tab, each `Tab` with its own content as its
  Children, where `Build` gives it the shown tab's alone. `Page` builds
  it from the controller's surface and state, so the controller's own
  view and the host's document are untouched.

A docs page:
```go
head.WriteString("<style>" + html.PageCSS() + "</style>")       // once
body.WriteString(html.New(view.NewController(nav), "nav").Page()) // a surface each
body.WriteString(html.New(view.NewController(doc), "doc").Page())
```

**The colours are the page's.** It sets SPEC §8's names on `<html>` or
any element around its surfaces (`--hotty-bg`, `--hotty-fg`,
`--hotty-accent`, `--hotty-ansi-8`, and `-9`, `-3`, `-2`, `-6` for error,
warning, success, info); page.css maps them to the kit's `--k-*` on the
surface itself, so a box around one surface may set its own. Missing ones
are the kit's default: `Canvas` and `CanvasText` (the page's own, for its
`color-scheme`), `GrayText` rules, and GitHub's blue, red, yellow and
green, light or dark by `light-dark()`. The docs pilot's palette is four
lines: `--hotty-bg: var(--page); --hotty-fg: var(--ink);
--hotty-accent: var(--accent); --hotty-ansi-8: var(--dim)`. A theme on
the rendition wins, and its surface is then a box of its colours
(`k-themed`). The type is the page's: the surface inherits its font.

**What a page shows** (profile §2.1 has the table):
- **Tabs**: every tab, a `section` each, named by its title, which is
  drawn as a tab bar of one tab (the tab shown's look), its content under
  it, in order. As GitHub shows the same Markdown.
- **HottyTree**: every node a row, the host's row, in `ul`s that nest as
  the nodes do. A branch is a `details` open or closed as given (expanded,
  and the branches the selection is in), its row the `summary`: the
  browser opens and closes it with no script, and the sheet draws its
  fold (`▸ ▾`) and its count, shown while it is closed. The selected
  node's label is `aria-current`. No filter.
- **Links**: one function (`pageLink`) decides every link on a page: in a
  Text's HTML (rewritten from goldmark's, whatever target it had), a
  Video's or AudioPlayer's, a tree node's. `http`, `https` and `//host`
  open in a new tab (`target=_blank rel=noopener`); any other (a path, a
  fragment, a query, `mailto:`, `tel:`) in the same tab; other schemes
  (`javascript:`, `data:`) lose their href.
- **Controls** show their state and take nothing, since no program would
  hear them: text and date fields are `readonly` (selectable, copyable),
  without suggestions' datalist; checkboxes, switches, sliders, selects
  (their picked option, closed), chips and Buttons take no click
  (`pointer-events: none`, a checkbox's label too) and leave the Tab
  order (`tabindex=-1`). A HottyForm is a `div role=form` (a submit
  would leave the page). A Modal is closed, its trigger alone.
- **Rows** show whole: a HottyTable's every row, a HottyList's every item
  (no filter, no dots), a HottyPaginator's child with every page's items
  and no dots (a bare one says which page shows, as on a host).
- **Left out**: HottyKeyHints (no key reaches a program) and toasts.
- **Still**: a Spinner's frame and a timer's time at the rendition's
  clock. An indeterminate HottyProgress sweeps by a CSS animation, 5 s
  across as on the clock, still under `prefers-reduced-motion`.
- Everywhere the host's `data-on`, `data-keys`, `data-steps` go, and so
  do a box's `tabindex`, the `grid`, `listbox` and `option` roles (the
  selected row is `aria-current`), and an open list's ARIA.

**KIT-26's tree links** wire in at one place: `pageTree` in
`rendition/html/page.go` calls `treeLabel(n.Label, "", i == sel)`; once
`view.TreeNode` has `Href`, the `""` becomes `n.Href`. `treeLabel` already
makes an `<a class="k-node-label">` through `pageLink`, `aria-current=page`
on the selected one (tested in `TestPageLinks`), and page.css styles it.
Text's links need nothing from KIT-26: page mode decides their target
anew, so whatever KIT-26 has the Markdown say on a host (a target, a
`data-` event) doesn't reach a page.

**How to see it.** `storybook -page STORY… > page.html` writes stories as
one page, or `-page -stream FILE` an A2UI stream's surfaces; `-theme`
applies. The page sets no palette, so the kit's default shows, light or
dark as the browser prefers. Pictures (`.shots/`, headless Chromium, and

**Follow-up, not in this leg:** a page host, the addon's surface code
(DOM, events, deltas) without the terminal, so that a WebAssembly program
running the kit makes the same HTML live. Progressive enhancement: the
page reads without it.

**Open for the maintainer:**
- Tab titles are styled `div`s naming their sections, not headings: the
  kit can't know the page's outline. A heading level the page passes in
  (an `h3` say) would put them in a reader's headings list.
- A link to the site's own absolute URL opens in a new tab: the kit can't
  tell the site from another. A page could pass its origin.
- Controls are drawn live-looking and take nothing. The other reading,
  drawing them disabled, was left: faint controls misreport the state.
- The default accent and signals are GitHub's (Primer) light and dark;
  any palette the maintainer prefers is four lines of page.css.
