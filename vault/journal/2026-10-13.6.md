# 2026-10-13.6 — Copy as a page copies, in cells

The maintainer: "OK, let's build the copy part. I want both hotty and
cell modes to feel browser-like. Let's also override ctrl+c, ctrl+v,
cmd+c,cmd+v - I think it's worth a try. There should be an option to
change it of course. The paste can be postponed for a bit later once I
play with copying".

**What a page does, and cells now does** (profile §3.7, "Copying"):
- Letting go of a selection, or a double or triple click, puts the text
  in the primary selection (OSC 52 `p`), as Firefox and Chrome do on
  Linux. It used to go to the clipboard (`c`), which a page never does on
  a select. Ghostty writes `p` to the primary selection on GTK. On macOS
  it has no pasteboard for it and drops it, so a select there leaves the
  clipboard alone.
- `Control+c` and `Meta+c` (Command+c) copy what is selected to the
  clipboard and keep it selected. That is the field's selection when a
  text control has the keyboard, else a Text's. A password field copies
  nothing. With nothing selected the key isn't the copy's: the storybook
  quits on `Control+c` as before.
- A page has one selection, so a press in one rendition drops the
  others' (`Rendition.Deselect`). A press on empty space in `-bare` does
  too.

**The option.** `cells.DefaultCopyKeys`, `Rendition.SetCopyKeys(keys...)`
(none: the program keeps every key), and in the storybook
`Options.CopyKeys` and the `-copy` flag (`-copy ""` for none). The bar
says "Ctrl+C copy or quit" while `Control+c` copies.

**API changes**:
- `Copied` returns a `cells.Clip{Text, Primary}`, and `Clip.OSC52()`
  replaces `cells.OSC52`. Nothing outside the kit used either.
- `Rendition.CopyKey` copies for a program whose selection is in a
  rendition without the keyboard.
- `Book.Selection` lets a program that keeps `Control+c` as its way out
  give the key to the Book while something is selected. The site's demo
  shell quits on Ctrl+C before the app sees it.

**Checked** in a pty with the built storybook (`-bare
basic/00_simple-text`):
- a drag over "Minimal" writes `52;p` "Minimal";
- `\x03` writes `52;c` "Minimal", and so does kitty's `CSI 99;9u` for
  Command+c;
- after a click on empty space, Ctrl+C quits;
- with `-copy ""`, Ctrl+C quits at once.

Tests: `TestCopyKeys`, `TestCopyField`, `TestOSC52` (both targets), the
selection tests on the primary target, and `TestCopyOrQuit` in the
storybook. A mutation run confirmed it catches a missing deselect.

**Not in cells:**
- Command+c reaches the program only from a terminal that doesn't keep
  it. Ghostty on macOS binds it to its own copy, and the site's page
  keeps every Command key for the browser.
- HottyCode and other components' text (a table's cells, a list's
  items) can't be selected: only a Text and a HottyMarkdown, its code
  blocks included, are painted through `paintText`.
- Paste: postponed by the maintainer.

**On a host** the selection is the host's: Blitz's document in
hottyterm, the iframe's in the addon. It went to hotty (message of
2026-10-13). The ask:
- hotty-blitz reads and clears the selection;
- hottyterm makes Ghostty's copy take a surface's selection, as
  `performable:` copy keys, so they pass through with nothing selected;
- the addon does the same with the browser's selection;
- SPEC §10.2's note ("Their GUI keys are the terminal's own: Control+c
  interrupts") changes with the maintainer's go, given here.
