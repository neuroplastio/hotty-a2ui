# 2026-10-13.1 — KIT-17c reviewed

The maintainer asked for a review of the file picker that landed on
2026-10-12 (1ce6bfc..da66a77), with the gaps fixed; hotty reviewed it too,
and its findings are in the same two commits.

**The view.** The highlight is an entry's name, kept per directory with its
first row (`FilePick.Dirs`), not an index: the restore on going up no longer
reads the directory a second time, and it holds where the agent moved `path`
(the old `dir != st.Path` branch overwrote it). A directory not shown before
highlights its first entry, as bubbles' does; before, only the root did. A
picker reads a directory when it shows it (`FileListing`), not at every
build, and again after a `Grant`. At the root, the keys that go up pass on,
so Escape closes a Modal around the picker. A literal `path` is where it
starts.

**The renditions.** `Label` and `SizeText` live on `view.FileEntry`, not
twice; cells names its hit codes; the host's entries are `~i`, as a
HottyList's items are, not the Slider's `~k`.

**The story.** The grant of `project` and the `filePicked` preview were in
`story.NewRun`, so every run (the chrome, a stream, every story) had both.
They are the program behind `hotty/filepicker` now (`story.Run.Program`,
`Play`). Its files are `story/fixture.json`, which `ref filepicker` writes to
a directory of its own, so that bubbles' picker lists the same files, as
ref's other components show their stories' content; it listed the working
directory before.

**The claims.** The catalog said the picked path was all the agent saw; it
sees each directory opened too (`path`, onChange). Grant's doc and §6.31 say
to grant `os.OpenRoot(dir).FS()`: `os.DirFS` follows a link out of its root.

**Deferred.** The host lists every entry of a directory (da66a77 moved to
the host's own scrolling): a cap or a window for very large directories is
the maintainer's call.
