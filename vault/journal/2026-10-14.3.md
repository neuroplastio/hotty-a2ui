# 2026-10-14.3 — Three of plexos's dialog-fit findings

plexos, fitting plx's settings dialog (its journal 2026-10-14.37,
DIALOG-FIT-01), found three kit quirks it worked around; the maintainer:
"You can fix the bugs."

1. **A List wore the scroll view's box on a host.** `stackClass` gave a
   scrolling stack (a List) the class `k-scroll`, the HottyScrollView's,
   whose later rule in kit.css adds a tonal fill, padding, a fixed height
   and a focus ring. A List's stack is now `k-overflow`, which only
   overflows; a drop's outline still finds it. plx's `dense.css` undoes
   it today and can drop that rule once on this commit.
2. **A blank row after a scroll view before nothing.** A Column sets a
   row after a HottyScrollView (it draws no edge), and did so before a
   child that draws no rows, an empty List, so plx's settings were 17
   rows in cells and 16 on a host. `separators` now gives no row before a
   child with no rows and passes it over: the next one is set apart from
   the one before it. The same in `columnHeight` and `paintColumn`.
3. **A scroll view's wrapped lines broke anywhere** (`/s/harn` /
   `ess/agy`). `scrollLines` now wraps as a Text does (`wrap`): between
   words, and a word longer than a row where the row ends, as the HTML's
   `pre-wrap` with `overflow-wrap: anywhere` does.

Tests: TestScrollViewOnHost (a List's class), TestScrollSetApart (an
empty List after the log, and between it and a Text; fails with the old
rule), TestScrollSideways (a line of words). The profile's Column rows
and the HottyScrollView row say so.
