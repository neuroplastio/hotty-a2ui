# 2026-10-14.4 — The edit keys on HOTTY's keymap, Mod and edit commands

The maintainer asked for copy, cut, paste and undo to be overridable from
the kit, with copy following the same rules as the others, and for no
double binding of Control and Command ("I don't want to bind both keys at
the same time"), keeping "HOTTY local and cells handle things in a
program", with feature parity non-negotiable. hotty landed it (SPEC
9f534fc and 6a03960: copy, cut, paste, undo, redo and select-all as keymap
actions; `Mod`; caps `mod` and `edit`; §10.6's `a=edit` and `command`;
hotty-go f458973). Then: "start".

**What changed in the kit:**
- hotty-go and its modules at f458973. `Resolve` and `ParseKeymap` take a
  `hotty.Platform`; `view.Controller.Platform` holds the host's
  (`hotty.PlatformOf` its caps), and the zero one is Control's, the
  maintainer's fallback for a program no host tells.
- Cells takes the edit actions from the keymap it already resolved for a
  field (`fieldKeymap`), and a Text's selection from the keymap of the
  element it starts in (`keymapIn`), as SPEC §11 has a host do: `copy`
  in `CopyKey`, `cut`, `paste` (the OSC 52 query, as before) and
  `undo`/`redo` in `editKey`. `SetCopyKeys`, `SetCutKeys`,
  `SetPasteKeys`, `SetUndoKeys`, `SetRedoKeys` and the `Default*Keys`
  are gone: a program overrides with its keymap (`SetKeys`, a component's
  keys), `Mod+c=program` keeping the key, the same in both renditions.
- `Rendition.Command(hotty.Command)`: a host's edit command (SPEC §10.6).
  A paste into a field whose keymap binds the key to paste types the
  text the command brought, no query and no prompt; one with no text does
  nothing; a menu's (no key) does what it names in the field, or copies a
  Text's selection. Any other command is its key: Command reports false
  and the program gives `c.Key` to `Key` through its own key path, so a
  key is never offered twice and Control+c with nothing selected still
  quits.
- The storybook: the Book keeps the host's caps (merging `caps` events),
  sets each pane's controller's Platform, takes all six commands when
  the host reports `edit` (`hotty.Edit`, again on a `caps` event), and
  routes `command` events (`Book.command`). `Options.Keys` and `-keys`
  replace `CopyKeys`… and `-copy`, `-cut`, `-paste`, `-undo`, `-redo`.
  The bar says "Ctrl+C copy or quit" while the keymap binds Control+c
  to copy.
- Key hints read `Mod` as the platform's key (`fieldHints`): `ctrl+a
  select all`, or `meta+a` on a Mac, where `home/ctrl+a` is line start
  (Cocoa's).
- Vectors take `mod`. The Command-keys vector plays in cells only, as a
  Mac (`mod: Meta`): hottytest reads every keymap with `Platform{}`
  (hottytest keys.go:90, :145) whatever its caps say, so a Mac host can't
  be played on it; told hotty.

**Checked:** the gate. TestCopyKeys (Control+c, not Meta+c, where Mod is
Control; the other way round where it is Meta; `Mod+c=program`;
`Control+C=copy`), TestCutPaste and TestUndo on keymap overrides,
TestCommands (paste with text, with none, copy left to Key, menu
select-all, copy, cut, undo, a paste bound to program), TestEditPlatform
(Meta+z, Meta+Z; Control+z not taken on a Mac), the storybook's
TestEditCommands (the `a=edit:take=…` sent on ready, a paste command typed,
copy with nothing selected quits), TestKeyHints on both platforms. The pty
checks of the bare storybook (no host): Control+v queries, the answer is
typed, Control+x cuts, a bracketed paste types; undo and redo by 0x1a and
0x19.

**Not checked:** a live host sending commands. hottyterm 740d7f8 isn't
released, and the installed hottyterm reports no `edit`, so there the
storybook keeps to keys.
