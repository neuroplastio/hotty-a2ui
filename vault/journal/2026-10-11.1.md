# 2026-10-11.1 — Page mode: what a page knows of itself

Two of KIT-24's four open questions (journal 2026-10-10.29) were the
docs' to answer, since KIT-24 is their request. They answered both
(2026-10-11), so the kit takes both from the page:

- **Tab titles as headings.** A docs page's tabs sit in its outline: under
  a `##` section, their titles are h3s. The page's contents (built from
  h2/h3) and a screen reader's heading list need that. The kit can't
  know the level around it, so the page passes it.
- **The page's origin.** A README written for GitHub links to the site's
  own pages absolutely (`https://kubecom.neuroplast.io/docs/install/`).
  The pilot treats these as site links, so they stay in the tab. Any
  other http(s) link opens a new one.

`Rendition.Page` takes `PageOptions{Heading, Origin}`:

- `Heading` 1–6 makes each Tabs title an `h<N>`, still in the tab's look:
  page.css zeroes the heading's margin and size, so the page's own heading
  rules don't reach it. Any other value leaves it a `div`, the default the
  docs asked for. No level is guessed.
- `Origin` is an origin (`https://x.io`; a bare host works too). Only its
  host counts, compared without case, so http and https to it both stay.
  A subdomain is another site.

The link decision is still one place: `site.pageLink` (the helpers are
methods of `site`, the origin's host). `storybook -page` passes
`Heading: 3`, since its stories' titles are h2s. Tests: TestPageTabs
(h3, and 7 is no heading) and TestPageOrigin. Checked the recipe card's
three h3 titles in headless Chromium: they keep the tab look.

Left for the maintainer: controls that look live and take no input, and
GitHub's colours as the default palette.
