# 2026-10-09.5 — KIT-02c and KIT-03c: progress and spinners on a clock

The first new components of phase 1, built as one leg because both need
time to move. Held against bubbles' progress and spinner (`make shot
NAME=progress`, `make shot NAME=spinner`).

**The catalog** (profile §6.6, §6.7):
- `HottyProgress` has `value` (DynamicNumber), `max` (default 1), `label`
  and `weight`. Without a value, or bound to a path that holds nothing,
  it is indeterminate.
- `HottySpinner` has `label`, `spinner` (bubbles' set names, default
  `dot`), `active` (DynamicBoolean, default true) and `weight`.
- Instructions 6 and 7 tell an agent how to use them.

**Cells** (profile §3.3, §3.4, §3.6):
- A progress bar is its label on a row, then the bar and ` 42%`.
  - The bar fills in eighths (`█` and `▏`…`▉`) and blends from `info` into
    `accent`, as bubbles' default blend runs across the bar. It is
    `success` once full.
  - The blend is a new cell property (`Cell.To`, `Cell.Mix`). It shows
    only where the theme colours both roles; at the ANSI-16 floor the bar
    is plain `info`.
  - Without a value, a quarter of the bar slides across, and the
    percentage's columns stay blank.
- A spinner is its frame in `info`, then the label after the set's widest
  frame. So the label never moves, while bubbles' does. A stopped spinner
  keeps the frame's columns blank.
- Spacing: progress bars and spinners count as controls. A labelled bar
  is set apart like a titled field, and a stack of spinners stays tight.

**The clock.** Frames follow the wall clock, not the number of draws.
- `Rendition.Animating` says when a draw wants the next one: the shortest
  interval it painted.
- `Rendition.Clock` lets a test fix the time.
- `storybook.Book.Tick` turns that into `tea.Every`. cmd/storybook returns
  it with each draw, and `storybook -bare` has its own.
- A program that embeds the Book must return `Tick` too, or nothing
  moves. hotty-demo's storybook app doesn't yet. The change is additive,
  and only its cells rendition would move.

**HTML and text** are baselines.
- On a host, the bar is a track with a fill, `role=progressbar` with its
  aria values. A spinner is `role=status` with its first frame, as wide as
  its widest frame, so the label stays put there too.
- Neither moves on a host. That is KIT-02h and KIT-03h.
- Checked with `hotty render` at 1.6×, default and Dracula.

**Split off:** KIT-03c's "pending state for async function values" is
KIT-WAIT under Later. The core resolves function calls at once, so there
is no pending state to draw yet.

For the maintainer to judge:
- the bar's colours: `info` blending into `accent`, `success` when done.
  bubbles blends purple into pink, and its bar stays that way at 100%;
- a blank row after a heading that comes before a control. Both
  references have one (`Progress`, then the bars). The kit has none,
  here or in the forms, because Text blocks stack tight (§3.4);
- the heavier Hamburger: its trigrams are wide since Unicode 16, so the
  kit gives them two columns, where bubbles' terminal gave one.

To see it: `storybook -bare hotty/progress` (Tab to the slider, then the
arrows move Download) and `storybook -bare hotty/spinner` (Space on
Working stops them), or the storybook pane.
