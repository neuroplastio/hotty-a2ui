# 2026-10-11.3 — KIT-25/26 merged; page mode takes their links

KIT-25/26 (`HottyMarkdown`, links in place; journal 2026-10-10.28) was
built on b36443c, before page mode. It came as a patch, committed at its
base and cherry-picked onto main (3d81e70). The Go code merged on its own.
The catalog took a 3-way JSON merge: HottyMarkdown went before HottyBigText,
instruction 27 before 28, and `anyComponent` was rebuilt from the
components. The catalog test and profile §6.27 to §6.29 kept both sides,
in order.

Page mode now draws what KIT-26 added:

- A HottyTree node's `href` is its label's `<a>`. This is the one change
  that `pageTree` was written for.
- A HottyMarkdown on a page is `pageDocument`: a link in place is an
  `<a href>` (the page's links then decide it: same tab for a path or a
  fragment), not the host's `span.k-link` with its click and Enter. A
  heading's id is its GitHub anchor itself, `usage`, not the host's
  `<doc>~#usage`, so that `page.html#usage` and `[x](#usage)` find it.
  Anchors are numbered across a surface, not across a page, so a page
  that shows several documents should keep them in one surface. The alert
  tags are now one function shared by host and page.

Checked in headless Chromium: the `hotty/markdown` story as a page,
opened at `#configuration` with JavaScript off, scrolls its box to
Configuration. Its links are `guide.md`, `#configuration`, `#faq`,
`reference/config.md` and `roadmap.md` in the same tab; Ada Lovelace's
Wikipedia link opens a new one. Test TestPageDocument covers the links,
the anchors (`usage`, `usage-1`), the tree's hrefs, and that no `k-link`,
`data-on`, `tabindex` or `~#` is left.

KIT-25/26's open points go to the feedback loop: IMPORTANT in the accent,
the missing gap after an alert before a list on a host, code with no fill
in a HottyScrollView, nothing marking the document focused after a jump.
The hottytest points (Space and Enter on a click span, Tab after a jump)
are hotty-go's, for the hotty agent.
