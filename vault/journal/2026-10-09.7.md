# 2026-10-09.7 — KIT-01c: HottyTable

The third phase-1 leg, held against bubbles' table (`make shot
NAME=table`, the cities of bubbles' example). The ref needed
`table.WithWidth`: bubbles v2 draws no rows without one.

**The catalog** (profile §6.8):
- `HottyTable` has `columns` (`key`, `header`, `width`, `align`), `rows`,
  `rowKey`, `selected`, `onActivate`, `height` and `weight`.
- `rows` is a list of objects, literal or bound. A list is one prop, not
  a template, so a big table is one component (L3), and the agent changes
  rows with `updateDataModel` (L5).
- The selection is the row's `rowKey` value, not its index, so it stays
  on its row as rows come and go. It is written to `selected`'s path,
  and `onActivate`'s context reads it from there (L2: select, then act).
- Instruction 8 tells an agent how.

**One window, both renditions.** The view decides which rows a table with
a height shows (`Element.Top`, kept in `State.Scroll`). It starts from
where it was and moves as little as brings the selection into view,
whether the user or the agent moved it. Cells and HTML draw the same
rows, side by side. On a host this replaces the host's own scrolling for
now: HOTTY can't scroll an element into view on command, so a keyboard
selection could leave the viewport. Native scrolling and a sticky header
are KIT-01h.

**Keys** are the controller's (`TableKey`), so both renditions move the
same way:
- the arrows move a row; Page Up and Page Down the body's rows; Home and
  End to the ends; with nothing selected, each selects the first row;
- Enter acts on the selected row.
- On a host the table is a `tabindex=0` box, which uses no keys (SPEC
  §10.2). Its `data-keys` bind the moving keys to `program` (§10.2, keys
  for the program, hotty 3c9b169), so a host that scrolls won't take
  them. Older hosts ignore the binding.
- A new key vector runs the cities story on cells and on hottytest's
  host.

**Cells:**
- A bold header, then a `─` rule in `border`. While the body scrolls,
  the rule ends with ` 4–10 of 12 `.
- Cells are padded a column each side, as bubbles has them. The widest
  columns give way first, down to 3, then cut with `…`.
- The selected row is reversed across the table: `accent` with the
  keyboard, `muted` without.
- A click selects a row. A click on the selected row acts on it.

**HTML:** a real `<table>` (Blitz lays one out). Its rows report clicks.
- `border-collapse: separate` is what makes the header rule draw. With
  `collapse` it doesn't.
- The rule is 2px, since a 1px straight edge drops out at 1.6×.
- The selected row's own background keeps it seamless.
- Checked with `hotty render`, default and Dracula.

For the maintainer to judge:
- the unfocused selection: reversed `muted`, a grey bar. Focused, it's
  `accent`;
- no box around the table, where bubbles draws one. The kit's Cards box
  things; a table in a Card gets one;
- the bold header (bubbles' example sets it plain);
- the position in the rule (`4–10 of 12`), which bubbles doesn't have.

Also from the maintainer: on a HOTTY host, hotty/progress's Indexing bar
doesn't move. That's KIT-02h, and it's next. The HTML rendition can follow
the same clock with a `var` delta per frame for the segment's place and a
`text` delta for a spinner's frame, so both renditions show the same
frame.
