# 2026-10-09.12 — KIT-05c: HottyCode

The seventh phase-1 leg: code, held against glamour's code blocks (`make
shot NAME=code`). Charm has no code component, but glamour draws a
Markdown code block with chroma, so no OpenTUI reference was needed. The
reference reads the story's own prose, as the viewport's does.

**Highlighting** is package `highlight`:
- chroma lexes a line at a time into tokens of twelve kinds (plain,
  comment, keyword, type, function, string, literal, meta, inserted,
  deleted, heading, invalid). The renditions colour a kind with a role,
  not with a chroma style. So every theme colours code, and at ANSI-16
  the terminal's own palette does.
- Tabs become spaces to the next stop of 4, so both renditions indent
  alike. A view is built again at every key, so `Lines` keeps the last 64
  codes it lexed.
- 37 languages come with the kit, copied from chroma into
  `highlight/lexers` (`make lexers`): what coding agents write most, and
  what those embed. Go's lexer is Go code in chroma, so
  `scripts/golexer.go` writes it as XML, with its raw strings as plain
  strings (chroma lexes Go templates inside them, with a lexer XML can't
  name).
- `highlight/all` adds the rest of chroma's lexers for a program that
  wants them. The site's storybook stays on the 37: they cost its TinyGo
  module 925 KB raw and 185 KB brotli (4.04 → 4.96 MB, 959 → 1145 KB).
  All of chroma would cost two to three times that, by an estimate
  without wasm-opt.

**The catalog** (profile §6.12, instruction 12): `HottyCode` has `code`,
`language` (a name, an alias or a file name), `lineNumbers`, `startLine`,
`marks` (a `line`, an optional `end`, and a kind: highlight, added,
removed, error or warning), `wrap` (true by default) and `weight`.

**Cells:**
- Each line is its number in `muted`, right-aligned, then the mark's
  sign when the code has marks, then the code. A wrapped line's further
  rows leave the gutter blank; without `wrap` a line is cut with `…`.
- Colours: keywords `info` and bold, types `info`, functions' names bold,
  strings `success`, numbers, constants and preprocessor `warning`,
  comments `muted` and italic.
- Keywords were `accent` at first. Profile §3.6 keeps accent for focus,
  so they're `info` and bold now, which also sets them apart from types.
- A marked line is tinted across its width. A cell can now have a
  background blended from the theme's background toward a role
  (`Cell.Back`, `BackMix`). A highlighted line takes the selection colour
  itself, and the other marks a sixth of their role's. There's no tint
  without a theme background or at ANSI-16; the sign still shows.
- A Text's fenced code blocks are highlighted the same way, indented 2.
- Natural width is the gutter and the widest line. The minimum is the
  gutter and 8 columns, or the widest line when that's narrower. A
  Column puts a blank row after code, as after a scroll view, since code
  has no edge either.

**HTML:** a `div` in the mono face on `--k-tonal`, a flex row per line
(number, sign, code), token spans of class `k-t-<kind>`, and a marked row
`k-m-<kind>`. Without `wrap` the host scrolls the box sideways (SPEC
§5.3). A Text's fenced blocks get the same spans. **Text:** the code with
numbers and plain signs (`>`, `+`, `-`, `✗`, `!`).
