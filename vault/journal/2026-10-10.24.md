# 2026-10-10.24 — KIT-14c: HottyTimer and HottyStopwatch

A phase-1 leg: a countdown that does something when it ends, and a
stopwatch, held against bubbles' `timer` and `stopwatch`. Story
`hotty/timer`, under Components: a stopwatch in tenths (`Lap`), started
and stopped with s and reset with r (two HottyShortcuts, as bubbles'
stopwatch example has them), a 25-minute timer as a clock (`Focus`), and a
10-second tea timer whose onTimeout shows a toast, with Start, Stop and
Reset Buttons whose checks read the path its `running` is bound to.

**The reference** (`ref/timer.go`, `make shot NAME=timer` with
`KIT_KEYS=`, `ROWS=14`, `COLS=60`): bubbles' timer and stopwatch with the
story's content, View as it is, and a help line for the stopwatch's keys.
Side by side, the rows are the same: `Lap 2.8s`, `Tea 8s`, the label, a
space and Go's way of writing a duration. bubbles has no clock format, so
its `Focus 24m58s` is the kit's `Focus 24:58`. bubbles draws no colour; the
kit's time is `muted` while it stands still (stopped, or run out),
checked in a second shot after the tea ran out and s stopped the lap
(`.shots/timer-done.png`: `Lap 11.3s` and `Tea 0s` muted, Start on, Stop
off, the toast).

**The catalog** (profile §6.25, instruction 25). Two components, as
bubbles has two packages, so that an agent finds the one it means by its
name; one view kind (`view.Timer`, Variant `timer` or `stopwatch`) draws
both.
- `HottyTimer`: `label`, `duration` (milliseconds, a DynamicNumber, as
  hottyToast's timeout is milliseconds; required), `running` (a
  DynamicBoolean, true by default), `interval` (1000, bubbles' default),
  `format` (`duration`, bubbles' look, or `clock`), `onTimeout` (an
  Action), `weight`.
- `HottyStopwatch`: the same without `duration` and `onTimeout`.
- `hottyStartTimer`, `hottyStopTimer`, `hottyToggleTimer`,
  `hottyResetTimer`, `{id}`, `rendererOrAgent`: bubbles' Start, Stop,
  Toggle and Reset. They are functions because basic's Button can't write
  the data model, and the agent steers the view by renderer functions
  (L8); a reset has no data-model form at all. Toggle is for one key or
  one Button that does both, as bubbles' `s`.

**Who keeps the time, and when onTimeout runs.** A2UI has no time (L6),
so the time counted is the surface's state (`State.Timers`, by node key),
counted on the rendition's clock at each draw
(`view.Controller.TickTimers`, before TickToasts, in cells' Draw and the
host's Doc and Update), as a toast's is: since the draw before, one that
counted then has counted that much longer. So a test sets the clock and
the time is exact, and two renditions drawn at once count it once.
- It walks the a2ui tree, not the view: a timer in a tab not shown counts
  and runs out on time, and the functions find it (`FindTimer`). A timer
  that goes from the surface loses its time.
- A timer runs out at the first draw at or after its end: it shows 0, its
  `running` is set false (written where it is bound, so that the agent
  and the Buttons' checks see it stopped), then its onTimeout runs, once,
  as its action, without the user's activation (no `openUrl` from it).
  Set running again once it has run out, it starts over.
- A start or a stop takes effect at the draw after it, which a program
  makes at once after each key, click or message. The rendition asks for
  a draw every tenth of a second while one counts, or every interval where
  that is shorter, down to a thirtieth (`view.TimerStep`), so the time
  shows, and a timer runs out, within that of when it should. Not aligned
  to the interval: the program's ticks fall on the epoch's multiples
  (`view.UntilStep`), and a timer's seconds fall where it started.
- The time shown is a whole number of intervals: a stopwatch's rounded
  down, a timer's time left rounded up, so that a timer shows 0 just as it
  runs out, as bubbles' does.

**Cells:** `Tea 4m59s` on one row, the label and a space, the time in
`fg` while it counts and `muted` while it stands still. A timer is a
control for the Column's separator, so a stack of them stays tight, as
spinners do.

**Host:** `span role=timer` (a screen reader does not read it at each
tick), the label, then the time in a span `~f` (the Spinner's frame's
letter: all 26 part letters are taken, and a part is a letter), so a tick
is one text's delta, in tabular figures, `k-still` (muted) while it
stands still. Checked with `hotty render` at 1.6x (hotty-blitz's release
build), running and stopped. Display type is KIT-14h.

**Text:** `Tea: 4m59s`, the time at the last draw.

**Checked:** `make check`; view tests (counting, rounding, running out
once and starting over, the functions from Buttons, a timer in a tab not
shown, the agent's reset, pruning, FormatTimer, TimerStep); cells (the
story's rows at 0 and 3.25s, colours, Animating, running out with its
toast and the Buttons' checks, Start from a click, s and r); host (deltas
a tick, k-still, Animating none once none counts, onTimeout); text;
catalog cases. The storybook in vhs, the story under Components, after 3
and 12 seconds. No vectors: a timer takes no keys (its shortcuts are
HottyShortcuts, which the vectors cover).

## Open, for the maintainer

- **Where the time goes in the data model.** The agent sees `running`
  where it is bound, but not the time counted: a stopwatch's time at a
  Lap or a Submit isn't in an action's context. An optional bound
  `elapsed`, written when it stops (not at each tick, which would rewrite
  the model ten times a second), would carry it; the action's timestamp
  covers simple cases meanwhile.
- **Width.** The time is as wide as it is (`9s` after `10s`), as
  bubbles' is, so anything after it on its row moves; the story keeps
  each on its own row. Reserving the widest width is possible for a
  timer (its duration's), not for a stopwatch.
- **Default format.** `duration` is bubbles' look (`4m59s`); `clock`
  (`4:59`) may read better to most people, and display type (KIT-14h)
  likely wants it.
- A Button that has the keyboard and then turns disabled (Stop, once the
  tea runs out) keeps the keyboard and its `enter press` hint, as any
  Button whose checks fail does. Not new here, seen in the done shot.
